# Feature: Compliance

## The invariant

Every participant is told they are interacting with AI; every AI-generated
artifact is marked with its provenance; the ledger's hash chain is verifiable
over any export range; and a retention policy can redact payloads without
breaking the chain.

## The boundary

This feature does **not** own:

- **The ledger** — the chain exists (`verify-chain.mjs`). This feature reads it.
- **Identity** — the `did` is client-asserted (`collaboration.md` names the
  gap). Compliance records the claim; it does not verify it.
- **Billing** — `model.usage` owns the numbers.
- **A legal opinion** — this feature implements the *technical* obligations of
  EU AI Act Article 50 and a SOC 2-shaped audit export. It does not assert
  compliance; it produces the evidence a compliance review reads.

Four rules this feature owns outright:

1. **AI disclosure is visible and persistent.** Every assistant message carries
   a visible AI marker; every agent suggestion carries "Proposed by AI"; the
   palette's agent actions are labeled. `aria-label` on the thread announces
   "AI assistant". Article 50's first obligation — *tell users they are dealing
   with AI, not a human* — is a UI element, not a legal footnote.
2. **Generated content is marked with provenance.** `artifact.persisted` and
   `artifact.shared` gain a `provenance` field: `{ generated: true, model,
   sessionId, generatedAt }`. The artifact pane renders a "Generated by AI"
   chip. The export carries the field.
3. **The chain is verified immediately before every export.** `integrity_status`
   is computed by a full `verify-chain` pass over the requested range and set to
   `VERIFIED` or `FAILED`. An export whose chain fails still generates — with
   `FAILED` in the manifest — so the failure is evidence, not a blocked action.
4. **Retention redacts payloads without breaking the chain.** A
   `session.retention` policy (default `keep-forever`; configurable down to a
   180-day floor) schedules a redaction job. Redaction replaces `payload_json`
   with a tombstone `{ redacted: true, type, hash }` and leaves
   `prev_hash`/`hash`/`id` intact — the chain still verifies, the content is
   gone. Article 50's six-month retention floor is the minimum the policy
   permits.

## The implementation

| File | What it provides |
|---|---|
| `functions/api/audit/export.ts` | the bundle: `manifest.json`, `events.jsonl`, `checksums.sha256` |
| `functions/api/audit/verify.ts` | `?from=&to=` — the chain verification over a range |
| `functions/_lib/retention.ts` | the redaction job: tombstone payloads past the window |
| `functions/api/session/[id]/retention.ts` | read/set the per-session policy, with the 180-day floor |
| `src/shell/compliance/AiDisclosure.tsx` | the persistent AI marker (thread + suggestion + action) |
| `src/shell/compliance/ProvenanceChip.tsx` | the "Generated by AI" chip on the artifact pane |
| `src/shell/settings/RetentionPanel.tsx` | the policy surface |
| `src/bus/events.ts` | *(modified)* `session.retention.changed`; `provenance?` on artifact events |

## The tests (negative controls in both directions)

| Test | Pass case | Fail case |
|---|---|---|
| disclosure visible | every assistant message carries the AI marker | a message renders unmarked |
| provenance marked | a generated artifact carries `provenance.generated = true` and the chip | an artifact renders unmarked |
| export verifies | the manifest's `integrity_status` is `VERIFIED` and `checksums.sha256` matches | an export claims VERIFIED on a broken chain |
| tamper is detected | mutate a row → the verify pass returns invalid | a mutated row passes |
| redaction preserves the chain | redact a payload → the chain still verifies | redaction breaks the hash |
| retention floor | a policy below 180 days is rejected | a 30-day policy is accepted silently |

## The gate

```bash
node scripts/gate.mjs --feature compliance
npx playwright test tests/e2e/compliance.spec.ts
```

The structural assertions are a precondition. The behavioural assertions are the
gate: (a) the AI marker renders on every assistant message and every suggestion;
(b) a tampered row fails verification; (c) a redacted payload leaves the chain
verifiable.

## The escalation

When this feature blocks a surface, the surface does not ship to a regulated
buyer. The ledger already has the chain; this feature is what makes it readable
to a compliance review — and Article 50's obligations are already in force.
