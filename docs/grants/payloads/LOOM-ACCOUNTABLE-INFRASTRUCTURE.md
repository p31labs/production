# NLnet Proposal — The Loom: Open-Source Accountable Agent Infrastructure

## The problem

AI agents are being deployed into workflows that touch money, care, and family data — but the record of what an agent actually did is usually a trace in a proprietary SaaS, replayable but not tamper-evident, and owned by the vendor. A regulator or a family cannot independently verify "what happened." The EU AI Act's Article 12 logging requirement for high-risk systems is one symptom; the broader failure is that agent accountability is locked inside closed platforms.

## The proposal

The **Loom** is an open-source, hash-chained agent audit layer. Every agent action is appended to a SHA-256 chain (RFC 8785 canonicalization), with optional ML-DSA-65 (FIPS 204) signatures. A pre-execution gate records *refusals*, not just actions — a denied action can never appear as if it happened. The chain is independently verifiable at a public endpoint:

```
curl -s https://b30e37b5.loom-8z0.pages.dev/api/loom-public/verify
```

The audit format aligns with active IETF work — `draft-sharif-agent-audit-trail-04` (JSON record, SHA-256 chaining, ML-DSA-65) and `draft-sato-soos-gar-02` (session audit record) — and implements the RFC 9943 SCITT model via Merkle batch anchoring.

## Why NLnet

- **Internet resilience**: a tamper-evident audit log that any third party can verify — no vendor lock-in on the evidence.
- **Privacy**: zero server-side identity store; the did:key lives on the device.
- **Open standards**: alignment to IETF drafts + SCITT, not a proprietary format.
- **Open source**: AGPL, open research (22 papers on Zenodo, all DOIs verified).
